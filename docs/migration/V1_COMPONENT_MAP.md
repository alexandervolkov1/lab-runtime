# Component map: v1 → lab-runtime

Статус: analysis, baseline и ограничения проверки — [inventory](V1_FEATURE_INVENTORY.md#baseline-и-границы-достоверности). Категория относится к указанной грануле, а не ко всему файлу. Наличие слова REUSE не разрешает сейчас копировать код.

REUSE — сохранить чистую логику почти без изменений; EXTRACT — выделить полезную логику, сняв зависимости; ADAPT — сохранить основу с изменением контракта; REWRITE — реализовать заново по поведению/тестам; DISCARD — не переносить структуру; DEFER — отложить функциональность за пределы первого POC. Тестовые группы T01–T16 раскрыты в [REUSE_PLAN](REUSE_PLAN.md#тесты-как-отдельный-актив).

## Вывод по гранулярности

Наиболее дорогие части переноса — не equations/codecs, а ownership и failure contracts вокруг них. C26–C28 намеренно разделяют algorithm/configuration/wrapper/Lua exposure; C36–C38 — recording semantics/service/storage/schema; C13–C21 — native model, wire compatibility, Lua host и lifecycle. Это запрещает делать вывод «перенести каталог src целиком».

Подробные controller state tables, Metakon metadata mapping, Lua capability routing и OutputControl lifecycle comparison находятся в [target-first map](V1_TO_LAB_RUNTIME_MAP.md). Там же описаны зависимости GUI от будущего общего API.
