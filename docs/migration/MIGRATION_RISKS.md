# Migration risks

Статус: статический анализ, baseline — [inventory](V1_FEATURE_INVENTORY.md#baseline-и-границы-достоверности). Здесь различены обнаруженные code properties и выводы о риске; это не список воспроизведённых аварий. Severity: critical — риск неверного physical output/ложного safe; high — потеря данных/управляемости/существенной feature; medium — migration debt/ошибочная compatibility.

## Приоритет обработки

До первого output test: R01–R06, R10 и минимальная boundedness R07. До физического recorder-required control: R08 и полный relevant evidence path. До real external slice: R11–R13, R17/R22. До POC acceptance: R07/R09/R14/R15 и lifecycle fault tests. GUI и richer parity позже не отменяют R18 как требование границы.

Ни один риск не требует менять high-level principles. R03/R10/R13/R16/R17 требуют уточнить контракты; предложения записаны отдельно в [ARCHITECTURE_FEEDBACK](ARCHITECTURE_FEEDBACK.md). Все реальные hardware safety values, limits и watchdog behavior остаются installation-specific, не выводятся из demo или тестов.
