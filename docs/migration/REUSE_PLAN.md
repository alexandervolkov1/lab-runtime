# Reuse plan и тестовые активы

Статус: план будущего переноса, без копирования production-кода. Baseline — [inventory](V1_FEATURE_INVENTORY.md#baseline-и-границы-достоверности), component IDs — [component map](V1_COMPONENT_MAP.md), target contracts — [основной mapping](V1_TO_LAB_RUNTIME_MAP.md).

## Direct algorithm reuse

REUSE относится к чистому математическому/codec kernel после выделения, а не к старому runtime wrapper. Поэтому основной component получает EXTRACT, даже если body equations не меняется.

| Asset | Почему сохранять | Условия / первый полезный этап |
| --- | --- | --- |
| Metakon CRC/encode/decode vectors, C10 | Маленькая изолируемая protocol-specific логика, проверка addresses/types/lengths | Native codec stage 3, убрать SerialConnection imports; не Modbus reuse |
| Virtual frame encoding/CRC/fragment parsing, C13 | Готовый corpus корректных/битых/fragmented frames | Optional wire adapter stage 3; native virtual stage 1 не требует wire compatibility |
| PID P/I/D-on-measurement + conditional anti-windup, C26 | Explicit dt, candidate-before-state-commit, полезные numerical tests | Stage 4, clock/quality wrapper новый; no claim of applied-output tracking |
| OnOff hysteresis, C27 | Простая проверенная state machine с boundary retention | Product parity после PID; timestamps/freshness проверяет новый wrapper |
| Furnace loss/feed-forward/predictor/PI, C28 | Реальный native algorithm с диагностикой и reproducible comparison fixtures | После PID vertical slice; equations сохраняются, defaults не объявляются tuning standard |
| Fixed/Ramp value-at-elapsed, C31 | Domain math независимо от Lua/hardware | Stage 4; runtime progression clock переписывается |
| EMA/mean/median kernels, C23 | Uneven-dt EMA, bounded windows, well-defined warm-up | EMA stage 4; добавить computed-output overflow tests и workload limits |
| Min/max display envelope, C47 | Endpoint/extrema/order/point-budget invariants | Future GUI; удалить egui types; не controller preprocessing |

## Extract after removing dependencies

- C03/C08: validation settings, per-series cadence/failure isolation; убрать shared SeriesStore/config mutation/GUI primary assumptions, inject clock.
- C12: Metakon register knowledge, scaling и sensor sentinel; generic executor не должен знать family fault codes.
- C15/C17: descriptor validation, model dispatch и late-response recovery; отделить wire framing от Instrument contract.
- C29/C30/C35: controller parameter knowledge, atomic multi-field config, output representability; отделить math от InstrumentValue dispatch/target commands/registry names.
- C36/C42: action completion before publication, safe-before-stop/retired-instance/rollback; переносить tests и constraints, не dependency graph старых services.
- C40/C41: strict unknown-key/type/range/duplicate-port/path rules из Lua; shared Rust validators должны защищать и Babashka/GUI/native clients.
- C44/C45: standalone host/listener lifetime separation, bounded framing/admission, accepted-vs-applied and outcome_unknown tests; не замораживать old JSON DTO.

## Adapt to new domain contracts

Typed descriptors/scales/units (C09/C12), virtual model equations/seeds (C21), generic graph cycle/removal knowledge (C24), scalar output conversion/SafeProfile knowledge (C35), recording event semantics и SQLite writer/schema (C36/C38). Во всех случаях добавить отсутствующий контекст: stable binding/generation/config revision, monotonic timing/quality, named operations/side effects, bounded resource/failure policies. Adapter не получает прямое право physical output.

SQLite остаётся обоснованным кандидатом, не автоматически утверждённым вечным storage engine. Существующие databases не изменять; schema compatibility/import — отдельная future задача.

## Rewrite behavior from tests/specification

Transport executor/worker scheduling wrapper (C04/C06/C07/C11), bounded signal ownership/processing service (C22/C25), controller/reference lifecycle (C29/C30/C32), OutputArbiter/trusted dispatch (C33/C34), bounded recorder service (C37), embedded Lua host/application API split (C39/C40), Runtime supervisor/external application mapping (C42/C44/C45).

Причина — несовместимость ownership/authority/clock/backpressure semantics, а не стиль кода. Например, тест «старый ACK не восстанавливает Automatic» ценен, но новый dispatcher должен дополнительно не отправить stale queued write вообще. Тест «recording failure не блокирует action completion» сохраняется, а «physical control бесконечно продолжается без required recorder» — нет.

## Do not migrate

- Family-specific Instrument enums во всех consumers и raw text write escape hatch для обычных clients.
- CombinedSource как обязательную domain hierarchy и AcquisitionSource как объединение polling/discovery/physical writes.
- Unbounded SeriesStore как одновременно domain registry, live history, recorder и GUI state.
- Автоматическое получение output authority при controller registration; Manual как подразумеваемый safe state; retry ambiguous writes без policy.
- Mandatory application Lua VM, global `app` как параллельный domain API, native callback blocking как якобы sandbox.
- Rust ScenarioService как встроенный full workflow engine target Runtime; script-side Fault/disabled buttons как safety authority.
- Direct GUI → shared SeriesStore/LuaHandle/ApplicationRuntime plumbing, static Lua help signatures как future external API specification.
- V1 SQLite schema/JSON DTO/loop names как вечные identity и compatibility constraints.

Удаление здесь означает «не переносить в новый проект», а не удалить что-либо в donor repository.

## Defer until GUI/full product stage

OnOff/Furnace и все filter variants после первого native PID slice; richer Reference Program/Script; полный Metakon register coverage после narrow driver slice; serial emulator compatibility UI; полноценные recipes/conditions/stages в Babashka; historical SQLite import/export; remote GUI, settings/file picker/help/control panels/downsampling integration. Длительные 24/72h runs — runtime candidate/pre-release, не admission gate первого архитектурного POC.

## Практический порядок будущей работы

1. Зафиксировать donor commit и взять test vectors/expected behaviors в новый test harness; не подключать v1 как runtime dependency.
2. Для каждой перенесённой гранулы указать source/provenance, new owner и compatibility delta; сначала pure math/codecs tests.
3. Перед I/O ввести minimal output authority и fixture с controlled effects. Old tests сравнивают behavior; новые tests доказывают дополнительные target guarantees.
4. Расширять public C/Q/E через один application boundary. Lua/GUI/Babashka adapters не дублируют validators/lifecycle.
5. В каждом milestone закрывать missing tests его risk boundary; не переносить весь suite со старой architecture ради количества green tests.

Первый implementation milestone описан в [POC_REFINEMENT](POC_REFINEMENT.md#первый-будущий-implementation-milestone). До отдельной команды пользователя — только эта документация.
